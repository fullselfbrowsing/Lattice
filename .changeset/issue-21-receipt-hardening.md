Harden capability receipts and fix the findings from issue #21.

- Signed `tripwireEvidence.observed` is now redacted for every invariant kind before signing. `no-pii` carries `{ detector, length, mask }` (letters and digits masked, separators kept); `must-cite`, `field-from-table`, and `matches` carry `{ valueType, length? }`; the `matches` message is replaced because schema issue text can embed the offending value. The manifest reasons are `no-pii-detector-mask-only`, `tripwire-observed-value-elided`, and `tripwire-schema-issue-elided`, and each entry is written at the moment of the rewrite. `result.error.evidence` from `ai.run` is unchanged. Breaking for consumers that read `observed.substring` from a signed body: switch to `mask`.
- New receipt schema `lattice-receipt/v1.4` with optional `audience`, `nonce`, and `expiresAt`. `createReceipt` accepts them, `ai.run` accepts `intent.receipt: { audience?, nonce?, ttlMs? }`, and `RECEIPT_VERSIONS` exports the ordered version list.
- `verifyReceipt(envelope, keySet, options?)` adds `minVersion`, `expectedAudience`, `expectedNonce`, `now`, and `maxAgeMs`, with the new error kinds `audience-mismatch`, `nonce-mismatch`, and `receipt-expired`. Binding checks run after signature verification. A receipt carrying `expiresAt` is rejected after that instant by every verifier, including replay and eval, so do not set `ttlMs` on receipts you intend to replay later.
- New `verifyChain(envelopes, keySet, options?)` on the root and `audit` entrypoints verifies a `parentReceiptCid` tree: every link, unique CIDs, one `runId`, exactly one root, parent linkage, and optional `expectedRunId`, `expectedCount`, and `expectedRootCid`. Dropped leaf receipts are only detectable with one of those commitments or an external anchor.
- `LatticeConfig.receipts.onSignerError` selects what `ai.run` does when a configured signer fails. `"flag"` (default) returns the run with `receiptError: { kind: "signer-failed", message }` and emits a `step.transition` event; `"throw"` emits `run.failed` and rejects with `ReceiptSigningError`. Receipts are minted before each terminal run event. The crew dispatcher records child receipt mint failures on the tracer instead of swallowing them.
- Crew agent completion receipts now carry `outputHash` over the agent's output, computed by the shared `hashOutputForReceipt` helper that `ai.run`, replay, and eval all agree on.
- Routing no longer adds the catalog position to a candidate's score. Ties resolve on provider and model identifier, so the same catalog contents produce the same route and fallback chain in any registration order. Behavior change for candidates that previously tied and were ordered by registration.
- `noPII` scans nested objects, arrays, and `[*]` wildcard results deterministically (array order, sorted keys, cycle guard, 32-level cap) and reports the concrete sub-path of the offending string. `us-phone` accepts dotted, spaced, and `+1` or `1` trunk-prefixed forms. `us-ssn` stays dashed-only; the detector module documents in-scope formats and the known SKU false positive.
- `inv.mustCite(name, { path?, keys?, caseInsensitive? })` locates nested citation arrays, compares other object keys, and matches case-insensitively. Defaults reproduce the previous behavior and keep `contractHash` stable.
- CLI: `lattice verify` gains `--min-version`, `--audience`, `--nonce`, and `--max-age-ms`; new `lattice receipt verify-chain <dir> [--key] [--expect-count] [--run-id] [--root-cid]` prints `OK root=<cid> links=<n>` or `FAIL kind=<kind> reason=<msg>`. Bad flag values exit 2 with `FAIL kind=invalid-argument`. `receipt diff` projects the new `audience`, `nonce`, and `expiresAt` fields.
